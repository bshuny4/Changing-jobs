# スクリーニング条件と検索クエリ

日次ルーティンが実際に叩く検索クエリの定義です。
**クエリの改善はこのファイルを編集するだけ**で反映されます（`prompts/daily-job-search.md` を触る必要はありません）。

---

## 探索方針（2026-08-08 変更）

依頼者の指示により、**大学職員系を主・民間を従**とする方針に変更しました。

- **範囲**: 情報系ポジションを優先しつつ、**大学の専任事務職員（総合職・配属未定）も対象に含める**
- **民間求人**: 探索は継続するが従。既に取得済みの民間候補6件は台帳に残し、比較対象として使う
- 配分の目安: 大学系チャネル（A/B/F）に7割、民間チャネル（C/D/E）に3割

> **承知しておくべきトレードオフ**: 大学職員系は年収非公開が通例で上限も頭打ちです。実際 8/4〜8/8 の5日間で、大学系求人は**すべて年収不明**でした。年収の具体値が取れたのは民間のみ（トヨタシステムズ835〜1160万、東邦ガス700〜850万）。**この方針では転職軸①「年収を上げたい」は実質的に評価しにくくなります。** 重み（年収40）の見直しは週次レビューの検討事項です。

## 最重要の探索テクニック（2026-08-08 確立）

**`allowed_domains: ["www.r-agent.com"]` を付けて検索すると、リクルートエージェントの個別求人URL（`/viewjob/` 形式）が直接取得できます。**

これは他のどの手法より到達率が高く、民間・大学職員のどちらでも有効でした。

| 手法 | 個別求人への到達 |
|---|---|
| 一般的なキーワード検索 | 4日間で1件 |
| 企業名・大学名を指定 | 企業ページ止まりが多い |
| **`r-agent.com` 限定検索** | **1クエリで3件** |

**毎日必ず、このドメイン限定検索を大学職員系と民間の両方で1本ずつ実行してください。**

推奨クエリ:
```
allowed_domains: ["www.r-agent.com"]
  1. 大学職員 学校法人 事務職員 愛知 名古屋 求人
  2. 大学 情報システム 職員 愛知 求人 情報基盤
  3. 社内SE 情報システム 愛知 名古屋 求人 転勤なし   ← 民間枠
```

doda・マイナビ・エン転職にも同様の個別求人URL形式がないか、順次試す価値があります。

## 探索チャネル一覧

大学系（A/B/F）を主、民間系（C/D/E）を従として回します。チャネルごとに狙う軸が違うので、**どれかが0件でも他が拾う**設計です。

| # | チャネル | 狙う軸 | 検証状況（2026-08-04 初回実行） |
|---|---|---|---|
| A | JREC-IN（大学・高専の技術職員／情報基盤センター） | 技術◎ 安定◎ | ✅ **個別求人に到達できた唯一のチャネル**。20件中12件が個別求人 |
| B | 愛知県内の大学の採用ページ | 安定◎ 技術○ | 🔺 採用ページには辿り着くが、個別の職種募集までは取れない |
| C | 一般転職サイトの社内SE／情シス | 年収○ 技術○ | 🔺 **一覧ページのみ**。個別求人0件。ただしスニペットに年収情報が出る |
| D | 公的機関・独法・自治体の情報系職 | 安定◎ | 🔺 一覧ページのみ。個別求人0件 |
| E | 高年収レンジ（スカウト系・Web系） | 年収◎ 技術◎ | 🔺 一覧ページのみ。個別求人0件 |

> **初回実行で判明した重要な傾向**
> 求人サイト（doda・Indeed・マイナビ等）は検索エンジンに個別求人を拾わせにくい構造のため、**C・D・E は求人一覧ページしか返しません**。一方で**スニペットには具体的な年収・勤務地・企業名が現れます**（例:「愛知県東海市・学校情報システム維持管理・予定年収500〜600万・残業ほぼなし」「豊田通商システムズ 社内SE 年収600〜899万」）。
> したがって C・D・E は「個別求人を取るチャネル」ではなく「**市場の相場観と、深掘りすべき企業名を拾うチャネル**」として扱ってください。拾った企業名は翌日以降「企業名＋職種」のクエリで再検索すると個別求人に当たる可能性があります。

## チャネル A — JREC-IN

日本の大学・研究機関の公募が集約されているポータル。**現職の経歴が最も直接的に効くチャネル**です。教員公募だけでなく技術職員・事務職員の公募も載ります。

```
WebSearch:
  allowed_domains: ["jrecin.jst.go.jp"]
```

クエリ（毎日すべて実行）:

1. `大学 情報センター 職員 求人 募集 愛知 名古屋 情報システム 技術職員`
2. `情報基盤センター 技術職員 募集 東海 中部`
3. `大学 情報システム 専任職員 募集 無期`
4. `高等専門学校 技術職員 情報 募集 愛知 岐阜 三重`

**注意点**
- JREC-IN は**教員公募（准教授・助教）が大量に混ざります**。「技術職員」「事務職員」「専門職員」以外は除外してください。
- 任期付きが非常に多いチャネルです。`never条件` に照らして丁寧に判定を。

## チャネル B — 愛知県内の大学 採用ページ

大学は自校サイトのみで職員募集を出すことがあり、JREC-IN に載らない求人を拾えます。

クエリ（大学名を差し替えて実行。毎日3〜4校をローテーション）:

```
{大学名} 職員採用 情報システム 情報センター 募集 2026
```

対象大学リスト:

| 区分 | 大学 |
|---|---|
| 国立 | 名古屋大学、名古屋工業大学、愛知教育大学、豊橋技術科学大学 |
| 公立 | 名古屋市立大学、愛知県立大学 |
| 私立（大規模） | 南山大学、名城大学、中京大学、愛知大学、中部大学 |
| 私立（その他） | 愛知工業大学、愛知淑徳大学、藤田医科大学、金城学院大学、椙山女学園大学 |

> ローテーション方式にしているのは、毎日全17校を検索すると検索回数が膨らむ割に更新頻度が低いためです。約5日で一巡します。

## チャネル C — 一般転職サイトの社内SE／情シス

年収レンジが明示されやすく、**年収軸で最も情報が取れるチャネル**です。

クエリ（毎日すべて実行）:

1. `社内SE 情報システム 転職 求人 愛知 名古屋 年収600万 募集`
2. `情報システム部 求人 愛知 正社員 内製 DX推進`
3. `情シス 転職 愛知 名古屋 ネットワーク セキュリティ 求人`
4. `社内SE 求人 名古屋 残業少なめ 年間休日120日以上`

主に拾えるサイト: doda / マイナビ転職 東海版 / エン転職 / Indeed / リクナビNEXT / type

**注意点**
- これらは**求人一覧ページがヒットしがち**です。個別求人でなく一覧ページだった場合は、レポートに「一覧ページ（個別求人は要確認）」と明記し、スコアは付けずに「参考」扱いにしてください。
- 掲載日が古い求人が上位に来ることがあります。3ヶ月以上前のものは注記を。

## チャネル F — 大学職員の求人（新設・2026-08-08）

**大学職員系の主力チャネル**です。JREC-IN（チャネルA）が5日連続で飽和したため、こちらを実質的な本命として運用します。

クエリ（毎日すべて実行）:

1. `大学職員 学校法人 事務職員 愛知 名古屋 求人` — `allowed_domains: ["www.r-agent.com"]`
2. `大学 情報システム 職員 愛知 求人 情報基盤` — `allowed_domains: ["www.r-agent.com"]`
3. `私立大学 専任事務職員 募集 愛知 名古屋 経験者採用 情報システム`
4. `大学 職員 中途採用 募集 愛知 名古屋 学校法人 専任職員 年収`

**大学職員求人の集約サイト**（週1回チェック）
- [大学職員求人News 愛知県49校](https://www.jobnews.jp/univ/saiyo/aichi) — ただし情報の鮮度が低い（2024年5月時点の掲載が混ざる）ため過信しない

**判定のポイント**
- **専任事務職員（総合職・配属未定）は技術軸を「不明」として扱う**（`job-axis.md` 参照）
- 大学職員求人は**年間休日・定年・残業時間が明記されやすい**傾向があります。安定軸の判定材料として積極的に拾ってください（例: 愛知学院大学 年間休日129日・定年62歳、名城大学 年間休日134日・定年65歳）
- 逆に**年収はほぼ非公開**です。不明を理由に落とさないこと

## 除外キーワード（全チャネル共通）

以下がタイトル・スニペットに含まれる場合は除外し、レポートの「除外したもの」に理由付きで記載します。

| キーワード | 理由 |
|---|---|
| 准教授、助教、教授、講師、ポスドク、研究員 | 教員・研究職。対象外 |
| アルバイト、パート、時給、派遣 | 雇用形態が対象外 |
| 新卒、既卒、第二新卒のみ | 対象外 |
| SES、客先常駐、特定派遣 | `never条件` |
| 営業、コンサルタント（技術職でないもの） | 職種が対象外 |

---

## 検索実行時のルール

- **チャネルA〜Eは互いに独立**なので、WebSearch を**並列で実行**してください
- 同一求人が複数チャネルでヒットした場合は、**URLで名寄せ**して1件として扱う
- 検索結果0件のチャネルがあっても、それ自体は異常ではありません。レポートに「チャネルX: 0件」と記録するだけで構いません
