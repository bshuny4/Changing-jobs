# 転職軸

求人を評価する物差しの定義です。日次ルーティンはこのファイルを読んでスコアリングします。

---

## 4つの軸と重み

| 軸 | 重み | 中身 |
|---|---|---|
| ① 年収軸 | **15** | 年収を上げたい |
| ② 技術軸 | **30** | 技術に深く関わりたい |
| ③ 安定軸 | **35** | 働き方・安定を保ちたい |
| ④ 適性軸 | **20** | 性格・働き方に合っているか |

合計100。週次レビュー（`prompts/weekly-review.md`）で、実際にどの求人に反応したかを見ながら調整していきます。

> **④適性軸を追加した理由**（2026-08-08）
> ①〜③は**条件**しか見ておらず、「入ってから毎日つらくないか」を測っていませんでした。雇用が安定していて年収も悪くないが、業務内容が本人の消耗パターンに直撃する求人が上位に来てしまう問題があります。
> **③安定軸との違い**: 安定軸は「雇用形態・残業時間・休日」という**制度**の話です。適性軸は「その業務を毎日やって消耗しないか」という**中身**の話です。残業が少なくても、業務が問い合わせ対応と調整ばかりなら適性軸は低くなります。

> **なぜ重み付けするのか**
> これらは同時に最大化できません。大学・公的機関系は②③に強いが①が頭打ち、事業会社の社内SEは①②が取れるが③の雇用安定性は下がる、SIer・受託は①が伸びるが③が崩れやすい。重みは「どれを諦めるか」の宣言です。
> 現状の 15/30/35/20 は「**安定を土台に置き、技術と適性で差をつける。年収は参考程度**」という意味になります。

> **2026-08-08 に 40/35/25 から変更した経緯**
> 探索方針を大学職員系（主）＋民間（従）に切り替えたためです。実測では、大学系求人は5日間で**一件も年収が公開されず**、年収の具体値が取れたのは民間だけでした（トヨタシステムズ835〜1160万、東邦ガス700〜850万、中部電力ミライズ500〜1200万）。年収に重み40を置いたままでは、大学職員系の求人が構造的に評価できません。
> **技術軸を35のまま据え置いた**のは、探索範囲を「情報系優先＋専任事務職員も含む」と決めたためです。これにより情報系ポジションが配属未定の総合職より確実に上位に来ます。

## 各軸の採点基準（5点満点）

### ① 年収軸（重み 15）

想定年収は求人票の「想定年収」「月給×12＋賞与」から読み取ります。

| 点 | 基準 |
|---|---|
| 5 | 想定年収 700万円以上 |
| 4 | 600〜699万円 |
| 3 | 500〜599万円 |
| 2 | 450〜499万円 |
| 1 | 450万円未満 |
| — | **不明の場合は「不明」と記載し、暫定 2.5 点**（推測で埋めない） |

**加点材料**（各 +0.5、上限5点）
- 昇給が年功ではなく評価連動と明記されている
- 賞与が年4ヶ月以上
- 資格手当・住宅手当など実質年収を押し上げる制度が明記されている

### ② 技術軸（重み 30）

**判定の基準線は「現職より手を動かせるか」です。** `career-profile.md` の「業務の内訳」の内製開発比率と比較してください。

| 点 | 基準 |
|---|---|
| 5 | 内製開発が主業務。技術選定の裁量がある。クラウド・自動化・IaC等が明記 |
| 4 | 運用・構築を自社で手を動かす。ベンダー管理も含むが技術的な意思決定に関与 |
| 3 | 社内SE。企画・調整とハンズオンが半々 |
| 2 | ベンダー管理・調整が主。手を動かす機会は限定的 |
| 1 | 純粋な事務・窓口対応。技術的な関与がほぼない |
| — | **判断材料がなければ「不明」と記載し、暫定 2.5 点** |

**減点材料**（各 −0.5）
- 「ベンダーコントロールが中心」と明記
- 「調整業務が中心」と明記

**異業種・異職種の求人の扱い**（2026-08-08 追加）

上の5段階基準は**情報システム職を前提**に書かれており、特許技術者・テクニカルライター・データ分析など**別職種には適用できません**。「内製開発が主業務か」という問いが成立しないためです。

異業種・異職種の求人では、技術軸を次のように**読み替えて**採点してください。

> **読み替え後の問い**: 「元SEの技術理解と、情報センターでの情報システム実務が、**この仕事の要件として実際に活きるか**」

| 点 | 読み替え後の基準 |
|---|---|
| 5 | 技術的素養が**必須要件**として明記され、かつ日常的に技術を使う |
| 4 | 技術的素養が必須または強い歓迎要件。実務で技術判断を伴う |
| 3 | 技術的素養が歓迎要件。あると有利だが必須ではない |
| 2 | 技術的素養はほぼ関係ない。ゼロからの職種転換に近い |
| 1 | 技術的素養がまったく活きず、これまでの経験が加点されない |

**読み替えを適用したときは、レポートに「異業種のため技術軸を読み替えて採点」と必ず注記**してください。情報システム職と同じ物差しで採点したように見せないためです。

**大学の専任事務職員（総合職・配属未定）の扱い**（2026-08-08 追加）

日本の大学の専任職員は**配属ローテーションが前提**で、求人票の時点では情報システム課配属かどうか決まっていないことがほとんどです。

このタイプの求人は、技術軸を**低得点（1〜2点）ではなく「不明」として扱い、再正規化で計算から除外**してください。

> **理由**: 配属未定は「技術に関われない」ことの証明ではなく、単に**情報がない**状態です。1〜2点を付けると大学の総合職求人が構造的に全滅し、依頼者が指定した「情報系優先＋専任事務職員も含む」という探索方針が成立しなくなります。
> ただし求人票に「情報システム課配属」「情報基盤センター配属」と**明記されている場合は通常どおり採点**します。また「配属は本人の希望を考慮」等の記載があれば、その旨をレポートの合致理由に書いてください。

### ③ 安定軸（重み 35）

| 点 | 基準 |
|---|---|
| 5 | 無期雇用・年間休日125日以上・残業月20時間以下が明記 |
| 4 | 無期雇用で、休日または残業のどちらかが良好 |
| 3 | 無期雇用。労働条件は平均的または記載なし |
| 2 | 契約社員だが正社員登用制度あり／残業が月40時間程度 |
| 1 | 任期付き・有期雇用で更新上限あり／みなし残業45時間超 |
| — | **雇用形態が不明なら「不明」と記載し、暫定 2.5 点** |

**加点材料**（各 +0.5、上限5点）
- 国立大学法人・独立行政法人・自治体など組織の存続性が高い
- リモート勤務・フレックスが制度として明記

### ④ 適性軸（重み 20）

**性格・働き方の適合度**です。本人のヒアリング（2026-08-08）に基づき、求人票の記述から機械的に照合します。

> **前提**: 性格そのものは測れません。この軸が測るのは「**求人票に書かれた業務内容が、本人が消耗すると答えたパターンに該当するか**」だけです。それ以上の推測はしないでください。

**本人の消耗パターン**（該当すると減点）

| # | 消耗する働き方 | 求人票の該当マーカー |
|---|---|---|
| 消耗1 | **締切・障害対応のプレッシャー** | 障害対応、インシデント対応、**CSIRT**、オンコール、24時間365日、夜間・休日対応、短納期、大規模プロジェクトの納期管理 |
| 消耗2 | **不特定多数からの問い合わせ対応** | ヘルプデスク、窓口対応、利用者サポート（が主業務）、問い合わせ一次受け |
| 消耗3 | **部署間の調整・根回し** | 調整業務が中心、折衝、合意形成、取りまとめ、**管理職・リーダー候補で調整比重が高いもの** |

**本人の手応えパターン**（該当すると加点）

| # | 手応えを感じる働き方 | 求人票の該当マーカー |
|---|---|---|
| 報酬1 | **仕組みを改善して効率が上がる** | 業務改善、効率化、自動化、RPA、**内製化**、DX推進 |
| 報酬2 | **人に感謝される** | 特定の相手を深く支援する性質の業務（研究支援、教育支援、専任担当制） |

**加えて**: 「**一人で深く掘りたい**」タイプ。少人数・専任・担当領域が明確なポジションは加点、大人数での分業や調整前提の体制は減点。
「新規立ち上げ／既存の安定運用」は**半々でよい**と回答があったため、**この軸では差をつけません**。

**採点基準**

| 点 | 基準 |
|---|---|
| 5 | 消耗マーカーなし。報酬マーカーが複数、または「専任で深く担当」が明記 |
| 4 | 消耗マーカーなし〜軽微。報酬マーカーが1つ以上 |
| 3 | 中立。または判断材料が乏しい（＝この場合は3を入れ、「判断材料不足」と注記） |
| 2 | 消耗マーカーが1つ、**業務の中心**として明記 |
| 1 | 消耗マーカーが2つ以上、業務の中心として明記 |
| — | 業務内容の記載が皆無なら「不明」（再正規化で除外） |

> **重要な区別（本人の回答から導出）**
> 本人は「不特定多数からの問い合わせ対応」で消耗する一方、「人に感謝されたとき」に手応えを感じると回答しています。矛盾ではありません。
> **広く浅い受け身の一次対応は消耗し、特定の相手に深く関わって解決した結果の感謝は報酬**という区別です。
> したがって「ヘルプデスク」「窓口」は減点、「研究支援」「専任担当として伴走」は加点、と扱い分けてください。この2つを同じ「対人業務」として一括りにしないこと。

## 総合点の計算

```
総合点 = (年収点 × 15 + 技術点 × 30 + 安定点 × 35 + 適性点 × 20) ÷ 100
```

小数第2位を四捨五入して表示します。

### 不明な軸がある場合：その軸を除いて再計算する（重要）

**「不明」に暫定点を入れて計算してはいけません。** 代わりに、**判明している軸だけで重みを再正規化**します。

```
総合点 = Σ(判明した軸の点 × 重み) ÷ Σ(判明した軸の重み)
```

例）年収=不明、技術=4、安定=3.5、適性=4 の場合
```
総合点 = (4×30 + 3.5×35 + 4×20) ÷ (30+35+20) = 322.5 ÷ 85 = 3.79
```

> **なぜこうするのか**
> 大学・公的機関の求人は**年収を公開しないのが普通**です。不明を2.5点として計算すると年収軸が総合点を常に引き下げ、**あなたの経歴が最も活きる大学系の求人が構造的に埋もれます**。実際に初回の試験実行でこの現象が起きました（名古屋大学の技術職員公募が 3.28 → 再正規化で 3.79）。
> 「情報がない」ことは「条件が悪い」ことではありません。両者を混同しないための仕組みです。

**2つ以上の軸が不明な場合**は、総合点の横に `判定保留` と付記します。判明している軸のいずれかが4点以上なら「要検討」に入れて構いません（情報が足りないだけで、有望な可能性があるため）。

| 総合点 | 扱い |
|---|---|
| **3.2 以上** | **要検討** — レポートの本編に詳細を載せ、`candidates.md` に追加 |
| 2.4 〜 3.1 | **参考** — レポートに1行で載せる。台帳には追加しない |
| 2.3 以下 | レポートの「除外したもの」に理由付きで1行 |

> **閾値を 3.5 から 3.2 に下げた理由**（2026-08-08）
> 3.5 という閾値は、民間の社内SE求人（4.5級が出る）を基準に決めたものでした。大学職員系は「年収3・技術3・安定4」のような**3点台前半に素直に着地する求人が中心**で、重みをどう組み替えても3.5には届きません。実際、東海市の大学職員求人は3案すべてで3.40〜3.45でした。
> これは求人の質の問題ではなく**閾値の設定ミス**なので、探索方針の変更に合わせて下げています。

## must 条件（1つでも欠けたら除外）

- **無期雇用であること**（正社員・専任職員・無期転換済み）
  → ただし雇用形態が**不明**な場合は除外せず、「要確認」として残す
- **想定年収 450万円以上**（500万円が目安、450万未満は明確に下回るため除外）
  → 年収が不明な場合は除外せず、「要確認」として残す
- **勤務地が愛知県内、または完全リモート可**
  → 県外でも、年収が650万円以上かつ技術軸4点以上なら例外的に残す（「条件次第で県外」の運用）

> **不明を除外に使わない理由**: 検索スニペットは情報が欠けがちです。不明を理由に切ると、良い求人ほど落ちる可能性があります。不明は「要確認」として残し、あなたが原典を見て判断してください。

## want 条件（加点材料。総合点に直接は効かないが、レポートで言及される）

- 大学・教育機関・研究機関（現職のドメイン知識が直接活きる）
- 認証基盤・ネットワーク・情報セキュリティの経験を求めている
- 社内の内製化・DX推進を進めるフェーズにある
- 情シスが「コストセンター」ではなく「攻めの部門」と位置づけられている
- 転勤なし
- 年間休日 120日以上

## never 条件（即除外）

<!-- ⚠️ 要確認：以下は初期案です。初回レポートを見てから調整してください -->

- **客先常駐がメインの働き方**（SES・特定派遣）
  → 前職SEで常駐がつらかったのであれば維持。そうでなければ削除を検討
- **みなし残業45時間超**
- **任期付き・更新上限ありのポジション**
  → 現職が安定しているため、そこを崩す転職は本末転倒という判断
  → ただし年収・技術で極めて魅力的な場合は？ 要検討
- **年収の記載が「経験・能力を考慮の上決定」のみで、レンジの手がかりが一切ない求人**
  → これは除外せず「要確認」に留めています（大学・公的機関に多いパターンのため）

> **調整のしかた**: `never` を厳しくすると精度は上がりますが、母数が減って「新着0件」の日が増えます。まず緩めに始めて、ノイズが多ければ絞るのが安全です。
