# Changing-jobs — 転職先マッチング日次ルーティン

自分に合った転職先を、毎日自動で探して記録していくための仕組みです。

- **対象**: 元SE → 大学職員（情報センター）というキャリアからの転職
- **勤務地**: 主に愛知、条件次第で県外も検討
- **転職軸**: ①年収を上げたい ②技術に深く関わりたい ③働き方・安定を保ちたい

---

## 中心にある考え方：4つの軸は同時に最大化できない

「年収UP」「専門性」「安定維持」「性格適合」は互いに引っ張り合います。実測では**適性が高い仕事ほど年収が低い**という傾向も出ています。

| 選択肢 | 年収 | 専門性 | 安定 | 適性 |
|---|---|---|---|---|
| 大学・公的機関の技術職 | △ 頭打ち | ○〜◎ | ◎ | ○〜◎ |
| 事業会社の社内SE | ○〜◎ | ○ | ○ | △〜○ |
| SIer・受託開発 | ◎ | ◎ | △ | △ |
| 特許・知財などの異業種 | △〜○ | ○ | ○ | ◎ |

だからこの仕組みは「おすすめ求人を並べる」ことをしません。**求人ごとに4軸を個別採点し、トレードオフを見えるようにします。**

毎日レポートを眺めるうちに、自分がどの軸に本当に反応するのかが分かってきます。週次レビューで軸の重みを調整していくと、「自分に合った転職先」の輪郭が数字で固まっていく — それがこのリポジトリの狙いです。

---

## 仕組み

```
                    毎朝 7:00 JST
                          │
                          ▼
        ┌─────────────────────────────────┐
        │  Routine（定期実行）             │
        │  prompts/daily-job-search.md    │
        │  を読んで実行                    │
        └─────────────────────────────────┘
                          │
       ┌──────────────────┼──────────────────┐
       ▼                  ▼                  ▼
  profile/ を読む   WebSearch × 5チャネル   candidates.md で
  （判断基準）       （求人を探す）          既出を除外
       │                  │                  │
       └──────────────────┼──────────────────┘
                          ▼
              must/never で足切り → 4軸スコアリング
                          │
                          ▼
              reports/YYYY-MM-DD.md を生成
              candidates.md を更新 → git push
                          │
                          ▼
        ┌─────────────────────────────────┐
        │  Routine のセッションに出力      │
        │  （会話にそのまま表示される）    │
        └─────────────────────────────────┘
```

**受け取り方は2通り**で、同じ調査結果です。

| 届き先 | 中身 | 向いている使い方 |
|---|---|---|
| **セッション** | 要検討の全件（スコア・懸念・次アクション込み） | 毎朝ここで読む。その場で追加調査を頼める |
| **リポジトリ** | レポート全文（除外理由・探索ログ含む） | 後から遡る。週次レビューの材料 |

> Routine はセッションに紐付いており、**毎朝レポートがその会話に届きます**。読んだあと「1件目をもっと詳しく調べて」「中京大学の年収を確認して」のようにそのまま会話を続けられるのが、この方式の利点です。

## ファイル構成

| パス | 役割 |
|---|---|
| `profile/career-profile.md` | 経歴・スキルの棚卸し。**あなたが埋める** |
| `profile/job-axis.md` | 転職軸の定義、重み付け、must/want/never条件 |
| `profile/screening-criteria.md` | 探索方針と検索クエリ群（大学系／民間系／異業種の3トラック） |
| `prompts/daily-job-search.md` | **毎日のルーティン本体**。Routineがこれを読んで実行する |
| `prompts/weekly-review.md` | 週次の振り返り。軸の重みとクエリを調整する |
| `reports/YYYY-MM-DD.md` | 日次レポート（自動生成・蓄積） |
| `reports/candidates.md` | 有力候補の追跡台帳。重複排除の参照元も兼ねる |

## セットアップ

外部サービスの連携は不要です。Routine のセッションに直接出力するだけなので、Webhook もシークレットも要りません。

やることは1つだけです。

### `profile/career-profile.md` を埋める

`<!-- 要記入 -->` の箇所を埋めてください。**未記入でもルーティンは動きます**が、埋めるほどスコアリングの精度が上がります。特に効くのは以下3つです。

- SE時代の技術スタックと担当工程
- 情報センターでの業務の内訳（手を動かす割合）
- 「一番うまくいった仕事 / 一番つらかった仕事」

> 「働き方の適性」セクションは 2026-08-08 のヒアリングで記入済みです。④適性軸はここを根拠に採点しています。

## 使い方

### 毎日

何もしなくて構いません。朝7時に Routine のセッションへレポートが届きます。
気になる求人があれば**リンクを開いて求人票を自分で確認**してください（後述の制約により、この仕組みは求人票の全文を読めません）。確認して分かったことをそのままセッションで伝えてもらえれば、スコアを更新します。

確認した求人は `reports/candidates.md` のステータスを更新します：

| ステータス | 意味 |
|---|---|
| `未確認` | 自動追加された直後 |
| `興味あり` | 求人票を読んで、応募を検討したい |
| `見送り` | 読んだが合わなかった（理由を書いておくと軸の調整に効く） |
| `応募済` | 応募した |

### 週1回

`prompts/weekly-review.md` の内容を Claude に実行させると、直近1週間を振り返って軸の重みとクエリの改善案が出ます。

### 手順を改善したいとき

`prompts/daily-job-search.md` や `profile/screening-criteria.md` を編集するだけで、翌日の実行から反映されます。Routine の再登録は不要です。

## 制約（正直に書いておきます）

この仕組みが動く環境では、外部への通信がネットワークポリシーで制限されています。実測した結果は以下の通りです。

| 手段 | 結果 |
|---|---|
| WebSearch | **動作する** |
| 求人サイトへの直接アクセス（doda, JREC-IN, Green, ハローワーク等） | **403 で全てブロック** |
| 外部サービスへの直接送信（Discord 等） | **403 でブロック** |

このため：

- **情報源は WebSearch のみ**です。求人票の全文は取得できず、レポートは検索結果のタイトル・スニペット・URLから組み立てられます。**必ず原典URLを開いて自分で確認してください。**
- スニペットから読み取れない年収・雇用形態は、推測せず**「不明」と書く**ようプロンプトで明示しています。求人情報の捏造は実害が出るためです。
- 外部への通知経路を持たないぶん、**結果はセッションに直接出す**方式にしています。外部サービスに依存しないので壊れる箇所がありません。

> **年収が取れない問題**: 5日連続で年収が判明した求人は0件でした。これは仕組みの不具合ではなく検索スニペットの限界です。**原典を1件開いて年収を教えてもらうだけで、その求人のスコア精度が一段上がります。**

### この仕組みがやらないこと

- **求人への自動応募** — 一切しません。判断材料の提示までで、応募はあなたの手で
- **求人サイトのスクレイピング** — 到達不可なため行いません
- **職務経歴書の自動生成** — 現時点ではスコープ外
