# Changing-jobs — 転職先マッチング日次ルーティン

自分に合った転職先を、毎日自動で探して記録していくための仕組みです。

- **対象**: 元SE → 大学職員（情報センター）というキャリアからの転職
- **勤務地**: 主に愛知、条件次第で県外も検討
- **転職軸**: ①年収を上げたい ②技術に深く関わりたい ③働き方・安定を保ちたい

---

## 中心にある考え方：3つの軸は同時に最大化できない

「年収UP」「技術深化」「安定維持」は互いに引っ張り合います。

| 選択肢 | 年収 | 技術 | 安定 |
|---|---|---|---|
| 大学・公的機関の技術職 | △ 頭打ち | ○〜◎ | ◎ |
| 事業会社の社内SE | ○〜◎ | ○ | ○ |
| SIer・受託開発 | ◎ | ◎ | △ |
| Web系事業会社 | ◎ | ◎ | △〜○ |

だからこの仕組みは「おすすめ求人を並べる」ことをしません。**求人ごとに3軸を個別採点し、トレードオフを見えるようにします。**

毎日レポートを眺めるうちに、自分がどの軸に本当に反応するのかが分かってきます。週次レビューで軸の重みを調整していくと、「自分に合った転職先」の輪郭が数字で固まっていく — それがこのリポジトリの狙いです。

## ファイル構成

| パス | 役割 |
|---|---|
| `profile/career-profile.md` | 経歴・スキルの棚卸し。**あなたが埋める** |
| `profile/job-axis.md` | 転職軸の定義、重み付け、must/want/never条件 |
| `profile/screening-criteria.md` | 日次検索で叩く検索クエリ群（チャネルA〜E） |
| `prompts/daily-job-search.md` | **毎日のルーティン本体**。Routineがこれを読んで実行する |
| `prompts/weekly-review.md` | 週次の振り返り。軸の重みとクエリを調整する |
| `reports/YYYY-MM-DD.md` | 日次レポート（自動生成・蓄積） |
| `reports/candidates.md` | 有力候補の追跡台帳。重複排除の参照元も兼ねる |
| `.github/workflows/notify-discord.yml` | Discord通知 |

## セットアップ（あなたの手作業は2つだけ）

### 1. Discord Webhook を GitHub Secrets に登録

1. Discord で通知したいチャンネル → 「チャンネルの編集」→「連携サービス」→「ウェブフックを作成」→ URLをコピー
2. GitHub のこのリポジトリ → Settings → Secrets and variables → Actions → New repository secret
3. Name: `DISCORD_WEBHOOK_URL` / Secret: コピーしたURL

> Webhook URL は誰でも投稿できる鍵です。**リポジトリのファイルには絶対に書かず、必ず Secrets に入れてください。**

### 2. `profile/career-profile.md` を埋める

`<!-- 要記入 -->` の箇所を埋めてください。**未記入でもルーティンは動きます**が、埋めるほどスコアリングの精度が上がります。特に効くのは以下3つです。

- SE時代の技術スタックと担当工程
- 情報センターでの業務の内訳（手を動かす割合）
- 「一番うまくいった仕事 / 一番つらかった仕事」

## 使い方

### 毎日

何もしなくて構いません。朝7時にレポートが生成され、Discordに通知が届きます。
気になる求人があれば**リンクを開いて求人票を自分で確認**してください（後述の制約により、この仕組みは求人票の全文を読めません）。

確認した求人は `reports/candidates.md` のステータスを更新します：

| ステータス | 意味 |
|---|---|
| `未確認` | 自動追加された直後 |
| `確認済-興味あり` | 求人票を読んで、応募を検討したい |
| `確認済-見送り` | 読んだが合わなかった（理由を書いておくと軸の調整に効く） |
| `応募済` | 応募した |

### 週1回

`prompts/weekly-review.md` の内容を Claude に実行させると、直近1週間を振り返って軸の重みとクエリの改善案が出ます。

### 手順を改善したいとき

`prompts/daily-job-search.md` や `profile/screening-criteria.md` を編集するだけで、翌日の実行から反映されます。Routine の再登録は不要です。

## 制約（正直に書いておきます）

この仕組みが動く環境では、外部への通信がネットワークポリシーで制限されています。実測した結果は以下の通りです。

| 手段 | 結果 |
|---|---|
| WebSearch | **動作する** |
| 求人サイトへの直接アクセス（doda, JREC-IN, Green, ハローワーク等） | **403 で全てブロック** |
| Discord への直接投稿 | **403 でブロック** |

このため：

- **情報源は WebSearch のみ**です。求人票の全文は取得できず、レポートは検索結果のタイトル・スニペット・URLから組み立てられます。**必ず原典URLを開いて自分で確認してください。**
- スニペットから読み取れない年収・雇用形態は、推測せず**「不明」と書く**ようプロンプトで明示しています。求人情報の捏造は実害が出るためです。
- Discord通知は GitHub Actions のランナー（通信制限なし）から行います。

### この仕組みがやらないこと

- **求人への自動応募** — 一切しません。判断材料の提示までで、応募はあなたの手で
- **求人サイトのスクレイピング** — 到達不可なため行いません
- **職務経歴書の自動生成** — 現時点ではスコープ外
